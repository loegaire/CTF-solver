Cooperative CLI-Driven CTF Solver (Native Execution)

1. Project Architecture & Philosophy

This system implements an Iterative Pair Programming (Ping-Pong) paradigm designed for maximum context awareness.

Both geminicli and copilot cli act as peer security researchers. By running natively alongside the target binaries (Environment Agnostic), the agents aren't restricted by a strict sandbox bridge. They can generate scripts that interact directly with the local filesystem, memory, and networking stack.

If Agent A writes an exploit that crashes, the Orchestrator hands the native crash log (e.g., GDB output, Python tracebacks) and the broken script to Agent B for a fresh perspective.

The Orchestrator (Python): The central referee. It manages the workspace directory, parses challenge files, maintains the context history, executes the generated scripts natively, and alternates tasks between the CLIs.

3. The Core Components

A. The User Entry Point (Directory-Based)

The Orchestrator operates directly on the local workspace directories.

Command: python orchestrator.py solve --dir ./workspace/pwn_buffer_overflow

Action: The Orchestrator scans the directory, catalogs all files, reads notes.md, and initializes the state machine right where it stands.

B. Tool Integrations (The Peer Wrappers)

Python wrappers using subprocess.run to interact with the CLIs. Because they run natively, you can prompt them to write investigative bash scripts as well as Python exploits.

Gemini Wrapper (geminicli): Highly capable at absorbing massive context.

Invocation: geminicli prompt "Here are the files: {file_list}. Here is the decompiled C. Write an exploit script. You may assume you have full local access to these files."

Copilot Wrapper (copilot cli): Excellent at specific syntax and rapid iterations.

Invocation: gh copilot suggest -t script "Fix this exploit script that failed with error: {error}. Context: {context}"

C. The Execution Environment (Native)

Instead of spinning up ephemeral sandboxes, the Orchestrator executes code natively.

It uses Python's subprocess.Popen to run the current iteration: python3 ./workspace/challenge_name/exploit.py

It captures stdout (looking for CTF{...}) and stderr (crashes, timeouts, tracebacks) directly from the host OS.

(Security Warning: Running untrusted CTF binaries bare-metal on your primary machine carries significant risk. If a challenge contains malware or a fork bomb, it will affect your host. If you choose to sandbox later, simply run this entire architecture inside a single Docker VM).

4. The Cooperative Execution Loop (The "Ping-Pong" State Machine)

This loop runs until the flag is found or the max iteration limit is reached.

Phase 1: Initial Assessment & First Strike

Orchestrator reads all files in the target directory and the notes.md.

Orchestrator sends the full context to Agent 1 (geminicli).

Agent 1 generates exploit_v1.py.

Phase 2: Native Execution & Evaluation
4. Orchestrator runs exploit_v1.py natively via subprocess.
5. Orchestrator parses the terminal output.

Success: Regex matches CTF\{.*?\}. System halts and prints the flag!

Failure: The script throws an error (e.g., EOFError, Timeout, Segmentation fault).

Phase 3: The Peer Review (The Ping-Pong)
6. Orchestrator gathers the context: The original goal, exploit_v1.py, and the Native Error Log.
7. Orchestrator appends this to iteration_log.md and passes it to Agent 2 (copilot cli).

Prompt: "Your peer wrote this script to solve the CTF challenge, but it failed locally with this error: [stderr]. Analyze the failure and provide a corrected script."

Agent 2 generates exploit_v2.py.

Phase 4: Continuation
9. Execute exploit_v2.py natively.
10. If it fails again, the new error and new script go back to Agent 1 (geminicli) for a deeper rethink.
11. The loop continues, bouncing between the two CLIs until the flag is captured.

5. Handling Edge Cases & CLI Quirks

State Tracking: Because CLIs are stateless, the Orchestrator maintains iteration_log.md inside the challenge directory. Every time it switches agents, it appends the previous script and error to this file.

Infinite Loops: Implement a MAX_ATTEMPTS counter (e.g., 10 iterations). If it fails 10 times, the Orchestrator pauses, dumps the current state, and asks the human operator to update the notes.md with a hint before resuming.

Regex Filtering: The CLIs will likely output markdown text alongside the code. The Orchestrator must use Regex to strip away the conversational text and extract only the raw code block before saving it to exploit.py.
